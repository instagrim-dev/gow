## 0. Read this section first — framing conflict and the resolution

The request was: *"perform gap analysis for remaining, mechanical, work
units to demonstrate a ES conjecture solution for v1.0.0 tag."*

That framing conflicts with this repository's own governing documents, and
the conflict is load-bearing enough to state before any checklist:

- `AGENTS.md`: *"Do not wait until `newf` solves Erdős–Straus. That would
  turn 'write the paper' into humanity's traditional method of never writing
  the paper."* Also: *"Evaluation before open-problem theater... Do not claim
  success because generated research prose looks sophisticated."*
- `EPIC.md`: *"The acceptance criterion is not 'solve Erdős-Straus.'"* And,
  in the v0 definition of done: *"Solving an open problem is not required for
  v0."* And in the v0 exit criteria: *"Solving a genuinely open problem is
  intentionally not a v0 exit criterion."*
- `corpus/README.md`: an earlier version of this same corpus mislabeled a
  split as a "historical holdout" and that claim was retracted as false. The
  document is explicit that folder separation is not a chronology and must
  not be cited as mathematical or historical evidence.
- `paper/PUBLICATION-PLAN.md`, "What does NOT block arXiv v1": *"A verified
  mathematical advance."*

There is also a plain mathematical fact this plan will not paper over: the
Erdős–Straus conjecture is open. The obstruction the corpus itself documents
(`corpus/experiments/pilot-004-discovery/quorum-adjudication-packet.json`,
`es-08-quadratic-reciprocity-obstruction`) is that every known congruence-
based construction is provably confined to quadratic non-residues, and no
covering system built from such constructions can reach the quadratic-residue
survivor primes (Mordell; sharpened by Elsholtz–Tao; still open as of the
most recent pre-cutoff source in this corpus, arXiv:2404.01508, April 2024).
**No sequence of engineering work units — CLI commands, schema migrations, CI
gates, or release tooling — can manufacture a resolution to that obstruction.**
A mathematical proof (or disproof) is a research outcome, not a mechanical
deliverable, and this project's own verification hierarchy (`docs/theory/`,
`paper/geometry-of-work.tex` §Epistemic model) requires such a claim to clear
**tier-1 (formal proof / deterministic check)** or **tier-2 (reproducible
computation)** before it counts as anything stronger than model judgment —
tiers `newf` has never populated for a live mathematical claim, and tiers no
gap-analysis checklist can pre-commit to reaching on schedule.

**Resolution — two decoupled tracks, not one blocked track:**

- **Track A (mechanical, schedulable, this document's real content):** the
  engineering gap between current repo state and a `v1.0.0` tag that honestly
  represents "the complete, reproducible GoW research substrate, using
  Erdős–Straus as its running case study" — the same scope `EPIC.md` already
  defines as "v0 definition of done," plus release engineering. This is
  fully mechanical and estimable.
- **Track B (mathematical, not schedulable, tracked but not gated on):** IF a
  live run of the existing frontier-generation/challenge/evaluation loop ever
  produces a claim that survives challenge, clears tier-1/tier-2 verification,
  and resolves (or narrows) the quadratic-residue-wall obstruction — that is
  an extraordinary, separately-announced research event. It is **not** a
  `v1.0.0` release-checklist item, has no estimable timeline, and this
  document defines the *plumbing* that such an event would need (§4) without
  claiming the plumbing causes the event.

If the operator's actual intent is "gate `v1.0.0` on a verified mathematical
resolution," that is a legitimate but different project than the one
`AGENTS.md` and `EPIC.md` currently describe, and cementing it would mean
formally amending those two governing documents first (§6, open question
OQ-1). Absent that amendment, this plan proceeds on Track A and treats Track
B as explicitly out-of-band.

## 4. Track B — what the plumbing for a real mathematical result would need

This section is **descriptive, not prescriptive**: it names the plumbing gap
(§1's rows on "tier-1 formal-proof integration" and "solution-artifact
domain type") that would need filling *before* a live research claim could
even be verified strongly enough to matter, without claiming any of this work
causes a resolution, or belongs on the `v1.0.0` checklist.

- **A tier-1/tier-2 verifier for Erdős–Straus-shaped claims.** Per the paper's
  own verification hierarchy (`paper/geometry-of-work.tex` §Epistemic model,
  and mirrored in `EPIC.md` M5.2), a claim of the form "`n` in residue class
  `R` admits `4/n = 1/x+1/y+1/z`" is deterministically checkable (bounded
  divisor search), and a claim of the form "no covering system built from
  mechanism family `M` can reach class `R`" is a proof-shaped claim needing
  either hand proof-checking or a formal-methods bridge (Lean/Isabelle).
  `internal/verify` has no such checker today; adding one is a well-scoped,
  code-only task **if and when** a candidate claim exists to check.
- **A domain type for a checked mathematical claim.** Neither
  `CandidateInvariant` nor `Evaluation` models "this statement about the
  target conjecture domain is true, checked by mechanism X, over scope Y."
  `internal/domain` would need a new type (name TBD, e.g.
  `DomainClaim`/`MathematicalResult`) carrying the same epistemic-status
  discipline (`ModelJudgment != Verification`) the rest of the system already
  enforces — this is consistent with, not a change to, the Hard Constraints.
- **An `establish` invocation with real independent evidence.** The
  `newf invariant establish` path already exists and is deliberately
  code-gated on operator-supplied independent snapshot evidence
  (`internal/invariant/challenge.go:19`). Nothing needs to change there; it
  has simply never been exercised because no invariant has cleared it.

None of the above is a `v1.0.0` blocker. It is recorded here so that *if* a
future live campaign (Track B) produces a serious candidate, the team knows
which plumbing gap to fill first rather than improvising ad hoc.
