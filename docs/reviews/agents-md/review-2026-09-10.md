## Verdict rationale

Every falsifiable factual claim in the contract **holds** against the repository (D7 fully green): all four named paths exist, `internal/domain` is clean of Cobra/SQL and of provider coupling, SQLite is confined to `internal/store`, and every package carries boundary tests. This document does **not** mislead.

It **buries**. The failure class is delivery (D1/D2/D9), not fact:

- The first 30 lines — the only region a token-pressured agent reliably reads before acting — are pure research philosophy. No identity-as-instructions, no hard constraint, no routing. First operative imperative ("provider identity must not leak into domain semantics") is at line ~48.
- The document has **zero bold spans**. A mechanical headings+bold compaction extract yields *topic names only*; all 8 `Do not…`/`Never…` constraints live as prose or list items and are dropped under compaction.
- The contract names **no build, test, vet, format, or commit command** anywhere, despite governing a Go repo where `go build ./...` and `go test ./...` work and tests exist in every package. An agent asked to finish work has no gate to run and no closure vocabulary to trigger one.

`buries` blocks a passing verdict identically to `misleads`; the distinction is diagnostic — the remediation here is **structural (restructure/front-load/promote)**, not factual correction.

### AMR-001 — No hard constraint or identity in first-contact zone
- **dimension:** D2 (first-contact ordering)
- **severity:** `agent-breaking`
- **breach:** D2 bar — identity, hard constraints, and the single most dangerous mistake must appear in the first ~30 lines.
- **location:** `AGENTS.md:1-33`
- **quote:** lines 1–33 are the title, the `failure-space -> … -> generalized frontier` loop, and the "Division of responsibility" ownership lists.
- **trigger:** P1 first-contact; P3 about-to-commit.
- **predicted_failure:** An agent that reads only the opening screen before its first edit will have absorbed research philosophy and zero actionable constraints. It will edit a domain type with a SQL import, or skip a boundary test, because the rules forbidding that sit 200–250 lines below the fold and never entered its working context.
- **proposed_rewrite** (`proposed — operator owns adoption`): insert immediately after the opening paragraph, before "The governing research loop":
  ```markdown
  ## Hard constraints (read first)

  - **Never put SQL or Cobra in `internal/domain`.** Domain types stay pure; SQLite lives behind `internal/store`, CLI wiring stays in `cmd/newf`.
  - **Never add provider coupling to a domain package.** Provider adapters live in `internal/provider`; domain records carry no vendor concepts.
  - **Never let an operation silently promote epistemic status** (`Hypothesis`→`Evidence`, `Candidate`→`Established`). Preserve the weaker type and record the limitation.
  - **Before you call work done:** `go build ./...`, `go test ./...`, `gofmt -l .` (must be empty). Add a test at the boundary where behavior is introduced.
  - **Read `README.md` and the relevant `docs/` file before changing architecture.**

  The rest of this document explains *why* these hold and how the research loop uses them.
  ```
- **confidence:** certain (deterministic scan) + corroborated by P1/P3 traces.

### AMR-004 — No failure-path guidance
- **dimension:** D8 (failure-path guidance)
- **severity:** `agent-degrading`
- **breach:** D8 — the contract never tells an agent what to do when the tree is dirty, the suite already fails, or concurrent edits collide.
- **location:** absent.
- **quote:** "—"
- **trigger:** P5 innocent-failing-test; observed live (concurrent writers landing `internal/normalize/`, `internal/provider/`, and a transiently build-breaking `internal/pipeline/normalize.go` during this very review).
- **predicted_failure:** Facing a pre-existing red suite or a broken concurrent file, the agent either halts on work that is not its own, or "fixes" an unrelated failure and expands blast radius, because no fix-forward-vs-report-vs-halt rule exists.
- **proposed_rewrite** (`proposed — operator owns adoption`): add a short section:
  ```markdown

  - A build/test failure in code you did not touch: report it; do not silently repair unrelated failures. Fix forward only within your slice.

  - A gate you cannot satisfy for reasons outside your change: record the blocker explicitly instead of declaring done.
  ```
- **confidence:** likely (probe trace + live observation).
